Ralph correctly identified the root cause in the verification loop (2025-12-02T010500Z):

**Problem:** Reconstruction helper at `dbex/refinement/reconstruction.py:238` applies `sqrt(spot_scale_override)` TWICE:
1. **Implicitly** via `scale_factor = exp(log_scale_baseline)` where `log_scale_baseline = log(sqrt(spot_scale))`

**Solution:** Remove the explicit `* sqrt_spot_scale` factor. The sqrt is already embedded in `scale_factor`.

## How-To Map

### Single Edit Required

File: `dbex/refinement/reconstruction.py`
Line: 238

```python
# CURRENT (wrong — double sqrt):
        bragg_scaled = bragg_panel * scale_factor * sqrt_spot_scale

# REPLACE WITH (correct — single sqrt embedded in scale_factor):
        bragg_scaled = bragg_panel * scale_factor
```

**Justification:** `scale_factor = exp(log_scale_clamped)` where `log_scale_clamped = log_scale_baseline + delta` for calibrated runs. Since `log_scale_baseline = log(sqrt(spot_scale_override))`, we have:

```
scale_factor = exp(log(sqrt(spot_scale)) + delta)
             = sqrt(spot_scale) * exp(delta)
```

The sqrt factor is already embedded. Multiplying by `sqrt_spot_scale` again produces `spot_scale * exp(delta)`, which is wrong.
