## Summary

Galph identified the root cause of persistent torch tensor zero-output in the canonical golden dataset: the incident beam orientation stored in the nanoBragg Simulator defaults to the sample→source vector rather than the required source→sample vector convention. This causes computed Miller indices to fall completely outside the structure factor grid bounds (h=[18,48] vs h=[-24,24], k=[14,53] vs k=[-28,28], l=[23,61] vs l=[-31,31]), resulting in 0% HKL hit rates and all-zero torch output. The loop produced a planning document, knowledge base entry, and prepared implementation instructions for the next actor (Ralph).

## Decisions/Rationales

- **Root cause attribution**: The HKL range mismatch (computed indices shifted +30) combined with the logged incident beam direction (0 0 1 = z-axis) and detector normal pointing toward sample proves the incident vector orientation is flipped. This is the most parsimonious explanation for the 0% hit rate and all-zero torch output across all prior attempts.

- **Single-source default fix required**: Multi-source code already implements the correct convention by negating source directions; single-source initialization path must follow suit for consistency and correctness.

- **Planning-only loop justified**: With dwell=8 (prior non-implementation loops confirmed), the loop focused on tracing the failure signature rather than immediately patching. This allowed precise root cause identification before delegating implementation.

- **Defer to Ralph for implementation**: The fix requires patching nanoBragg source code (vendored dependency) and regenerating golden tensors; the next loop actor is better positioned to execute the patch, rebuild, validate with DB_AT_001, and coordinate fixture updates.
