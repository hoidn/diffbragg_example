## Decisions/Rationales

- **Unified helper approach**: Rather than patching Stage A chi-squared separately, extract a single shared variance-weighted loss helper at the top level of `run_nanobrag_refinement` so Stage A/B/C all consume it with one precomputed `sigma_floor_sq` tensor. This prevents formula drift and simplifies telemetry/clamp-fraction tracking.
- **Shared sigma_floor_sq tensor**: Pre-compute the variance floor as `sigma_floor_sq = max(1.0, sigma_floor_value**2)` once per refinement to avoid repeated clamping logic and ensure all stages observe identical floor.
- **Reuse for telemetry**: The helper output (loss value and clamp fraction) feeds directly into RefinementTelemetry, eliminating separate tracking paths per stage.

## Errors/Failures

- **Stage B NaN/Inf gradient** (confirmed): LBFGS optimization terminates immediately when gradient guard detects NaN/Inf in parameter tensor. Occurs despite sigma-floor guard; root cause likely that Stage A's legacy ratio-of-sums formula produces different scale/numerics than Stage B/C per-pixel approach, causing denominator instability.
- **Stage C gate mismatch** (confirmed): Stage C improvement check compares Stage A final chi-squared (ratio-of-sums formula) against Stage C final (per-pixel sum), mixing incompatible units by ~10,000x. Gate calibration assumes Stage A/C use same scale (spec-db-core.md:57-68).
- **Suspected root cause**: Stage A's chi-squared computation at lines 766-795 of `dbex/nanobrag_refinement.py` divides `sum((I_model - I_obs)^2)` by `sum(variance)` instead of summing per-pixel `(I_model - I_obs)^2 / variance`. This violates the spec-defined chi-squared and causes both the gradient instability and gate mismatch.
