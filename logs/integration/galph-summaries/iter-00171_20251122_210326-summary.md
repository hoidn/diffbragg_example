# Iteration 00171 Summary

## Summary

Iteration 171 focused on diagnosing quaternion U-matrix convergence failures in the TORCH-GEOMETRY-CONVERGENCE-001 initiative. Ralph executed Phase B1 LBFGS testing to validate an alternative optimizer following the discovery of a B_ideal mismatch bug in Phase A. The iteration revealed that while the B_ideal bugfix (commit 826f4c9) successfully resolved initialization pathology in the zero-point check path, a deeper code path divergence persists in the optimization loop, causing catastrophic chi-squared failures when using quaternion U-matrix parameterization.

## Key Actions

- **Phase A Bugfix Completion**: Refactored `derive_u_matrix_from_mosflm_a_star` helper to return both U_matrix and B_ideal_reciprocal from the same computation, eliminating mismatch between cctbx and TorchCrystal B_ideal calculations (commit 826f4c9)
- **Zero-Point Validation**: Confirmed B_ideal bugfix works correctly in zero-point check path with chi² = 989,645.5 and correlation = 0.9999999843
- **Phase B1 LBFGS Test Execution**: Implemented LBFGS optimizer infrastructure (config field, CLI flags, closure pattern) and executed test with two diagnostic reruns
- **Telemetry Path Fix**: Corrected double-prepending bug in artifact path construction during diagnostic rerun
- **Code Path Divergence Diagnosis**: Identified critical finding that zero-point check (use_mapping_zero_geometry=True) produces chi² = 989k but LBFGS optimization loop (use_mapping_zero_geometry=False) produces chi² = 1.425B at step 0
- **Regression Guard**: Validated `test_stage_a_expansion` passes (13.16s), confirming default cell+misset path unaffected

## Decisions/Rationales

- **B_ideal Mismatch Root Cause**: Two separate code paths computed B_ideal using different methods (TorchCrystal vs cctbx fractionalization_matrix), causing U @ B_ideal ≠ A_star_mosflm at initialization. Rationale: Bugfix by consolidating to single TorchCrystal computation path ensures mathematical consistency.
- **LBFGS Test as Primary Hypothesis Test**: LBFGS selected over continued Adam tuning because it eliminates momentum (hypothesis H4), uses line search to mitigate exploding steps (H3), and is proven for scale-only refinement per REFINE-001 precedent.
- **Escalation to Deep Diagnostic**: Phase B1 test timeout (CPU performance ~600s/step, 2/10 steps completed) combined with persistent chi² catastrophe at step 0 despite bugfix indicates deeper B_ideal tensor mismatch in optimization closure. Decision: Defer LBFGS as alternative optimizer pending root cause identification.

## Errors/Failures

- **LBFGS Test Timeout**: First diagnostic run completed only 2/10 optimizer steps before timeout (1200s limit on CPU), insufficient for convergence validation. Root cause: CPU evaluation of Bragg tensor computations for line-search backtracking.
- **Telemetry Path Duplication**: Artifact paths double-prepended (`plans/.../2025-11-22T165000Z/plans/.../2025-11-22T165000Z/telemetry/`) in initial B1 run due to script bug. Fixed in diagnostic rerun.
- **Persistent Chi-Squared Catastrophe**: Despite B_ideal bugfix, step 0 chi² = 1.425B in LBFGS test, matching pre-bugfix PARITY-003 failure signature. Indicates B_ideal mismatch persists in optimization loop despite working correctly in zero-point check path.
