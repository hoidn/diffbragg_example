## Decisions/Rationales

- **Root Cause:** Stage A now forces `force_panel_validation=True` when `enable_stage_c=True` per REFINE-FLOW-001. Stage C, however, inherits ROI-mode closures that evaluate only the subset of pixels in canonical ROI regions, so when Stage A reports panel-wide chi-squared (all pixels), Stage C reports ROI-subset chi-squared; the REFINE-007 gate compares these different populations and incorrectly flags a regression
- **Solution Approach:** Propagate the `force_panel_validation` flag through Stage A telemetry (new `validation_scope` field) and wire it into Stage C context. When panel scope is requested, Stage C's `compute_loss` calls for "full" validations will bypass ROI sampling, ensuring both stages measure identical pixel populations
- **Scope Boundaries:** Changes remain within stage_a.py, stage_a_impl.py, stage_c.py, and stage_c_impl.py; warm-cache factory helpers and shared simulator code are out of scope to avoid unintended interactions
- **Preservation:** ROI-mode closures for Stage C sampling remain active during canonical/warm optimization runs; only final/baseline full validations switch to panel mode when requested
