- **Torch Reinstallation Strategy**: Rather than attempting targeted symbol fixes, chose complete package uninstall and reinstall from official PyTorch repository, which is the standard remediation for CUDA mismatch issues. This approach isolates the problem to environment/dependency layers rather than corrupted binary artifacts.

- **Parallel Symbol Investigation**: While attempting DiffBragg capture, simultaneously investigated whether the symbol was present in bundled libcudart to rule out incomplete library installation. This confirmed the symbol IS available, shifting root cause hypothesis away from missing CUDA runtime toward Python module loading or compiled extension incompatibilities.

- **Cache Clearing**: Proactively cleared Python bytecode cache on the hypothesis that old torch module metadata was being retained in .pyc files. While this had no effect, it rules out a common source of Python import issues.

## Errors/Failures

### Critical Blocker: torch CUDA Symbol Error in dbex.refine_one

**Error Message**:
```
ImportError: /home/ollie/miniconda3/envs/simtbx/lib/python3.9/site-packages/torch/lib/libc10_cuda.so:
undefined symbol: cudaGetDriverEntryPointByVersion, version libcudart.so.12
```

**Occurrence**: When executing `python -m dbex.refine_one --backend diffbragg ...`, the error occurs during import of `score_trainer.roi_check` which imports `torch` and `torchvision`

**Paradox/Evidence of Root Cause Complexity**:
- torch 2.8.0+cu128 reinstalled successfully from official PyTorch repository
- torch imports successfully in isolated Python REPL sessions: `python -c "import torch; print(torch.__version__)"`
- Symbol `cudaGetDriverEntryPointByVersion` IS present in bundled libcudart: verified via `nm -D`
- Bundled libcudart.so.12 loaded correctly as dependency of libc10_cuda.so
- Yet dbex.refine_one fails with identical error in subprocess/module context

**Suspected Root Causes**:
1. **Python module cache corruption**: Old torch modules may be cached in import system despite bytecode deletion
2. **score_trainer compiled extensions**: score_trainer may have been compiled against old torch binary, with hardcoded references to old symbol addresses
3. **Dynamic linker cache staleness**: System-level library loader (ld.so) may be caching old torch library paths; requires `sudo ldconfig` to refresh
4. **Environment variable leakage**: Bash subshells may not respect updated PYTHONPATH or LD_LIBRARY_PATH settings from torch reinstall

**Impact**: Prevents Phase A2 (DiffBragg baseline) and downstream phases A3, B1-B3, C3 from proceeding.
