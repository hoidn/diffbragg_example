## Decisions/Rationales

1. **Patch-Based Approach:** Four localized patches were applied to `capture_forward.py` rather than waiting for full downstream API updates. Rationale: minimize disruption to frozen environment while unblocking critical capture flow.

2. **flex.double Conversion:** numpy arrays cannot be passed directly to `customized_copy(data=...)`. Conversion to `flex.double` matches the DIALS/cctbx expected interface for reflection data.

3. **Polarization Fraction Removal:** The `nanobrag_torch.config.BeamConfig` class does not accept `polarization_fraction` as a constructor argument; removal prevents runtime AttributeError.

4. **JSON Serialization Fix:** Numpy scalar types (e.g., `np.float32`) are not JSON-serializable; explicit `float()` conversion ensures metadata files pass JSON validation.

5. **Partial Metrics:** Since the canonical capture produces raw tensors but correlation/RMSE require comparison with a reference forward pass, placeholder metrics are sufficient for D1 evidence gathering; full metrics will be computed by the parity harness.
