## Errors/Failures

### Critical: Torch Simulator Zero Output
**Symptom:** All panels contain zeros despite verified non-zero structure factors passed to simulator.

**Suspected Root Causes:**
1. **HKL Indexing Mismatch**: Structure factors may be indexed using DiffBragg/DIALS conventions while torch simulator expects different h,k,l sign/origin conventions. Grid construction maps (h,k,l) indices linearly; any offset would silence entire grid.
2. **Energy/Wavelength Mismatch**: DiffBragg (12.69 keV) vs torch config may have wavelength disagreement causing zero scattering angle for all reflections.
3. **Detector Convention Mismatch**: `TorchDetectorConvention.DIALS` vs actual dxtbx orientation may cause panel offset/rotation, landing all predictions off-detector.
4. **Crystal Orientation Bug**: Misorientation angles (α, β, γ) passed as `misset_deg` may be zero when they should match UMAT from DiffBragg refinement.
5. **Torch Package Bug**: nanobrag_torch 0.1.0 may have regression or missing normalization step in simulator forward pass.

**Evidence:**
- log entry: "fluence=1.000e+18, flux=1.000e+12, exposure=1.0" confirms parameters reach simulator
- HKL grid construction shows non-zero amplitudes placed into grid
- No exceptions raised by torch code; silent zeros throughout

**Attempts to Resolve (3 iterations):**
1. **Iteration A**: Added explicit flux/fluence/exposure parameters (prior log showed missing from older capture_forward.py)
   - Result: Parameters logged correctly but output still zero
2. **Iteration B**: Added HKL instrumentation to verify in-range fraction and grid_nonzero count
   - Result: Metadata shows structure factors present but not translated to output
3. **Iteration C**: Inspected nanobrag_torch config construction for matching DiffBragg physics
   - Result: All visible fields set correctly; no obvious bug found in parameter mapping

## Errors/Failures (continued)

### Secondary: Missing Full-Panel DiffBragg Baseline
**Symptom:** DiffBragg refinement generates ROI-level HDF5 (92 × 12×12 arrays) but no full-panel tensors for comparison metrics.

**Root Cause:** `dbex.refine_one` stores interim ROI scores during refinement but does not export a final full-panel `[panel, slow, fast]` forward prediction. Attempting to call `diffBragg_forward` after refinement triggers diffBraggCUDA.cu:708 assertion (documented in DIFFBRAGG-001).

**Impact:** Cannot compute correlation/RMSE between DiffBragg and torch on same coordinate system. Parity metrics blocked until full-panel baseline available.
