## Decisions/Rationales

**Decision 1: Use reciprocal vectors for Miller indices**
- **Rationale**: Aligns with docs/architecture/parameter_trace_analysis.md:47 which states Miller indices use reciprocal vectors. Per crystallographic convention, the scattering vector q should be projected onto reciprocal basis (a*, b*, c*) not real space (a, b, c).

**Decision 2: Apply unit conversion (m^-1 → Å^-1)**
- **Rationale**: Scattering vectors computed in detector code are in m^-1. Reciprocal vectors are in Å^-1 (standard crystallography units). Conversion by dividing by 1e10 ensures dimensional consistency.

**Decision 3: Implement proper broadcasting for tensor operations**
- **Rationale**: Match existing broadcasting pattern used for rot_a/rot_b/rot_c to maintain consistency and avoid shape mismatches in batched/multi-source computations.

**Decision 4: Log once per panel only**
- **Rationale**: Per input.md:34, logging must stay bounded (<100 lines) to prevent canonical_capture.log bloat while still providing useful diagnostics.

### Critical Finding: 0% HKL Hit Rate (BLOCKING)

**Symptom**: Structure factor lookups return all zeros despite reciprocal vector fix.

```
HKL hit rate: 0/6,224,001 pixels (0.00%)
DiffBragg baseline: max=36182.91 (non-zero ✓)
Torch baseline: max=0.0 (all zeros ✗)
```

**Root Cause Analysis**:
The fix correctly addresses two known issues:
1. ✓ Using reciprocal instead of real-space vectors
2. ✓ Converting scattering vector units (m^-1 → Å^-1)

However, the **0% hit rate persists**, indicating computed h,k,l values are NOT landing within structure factor grid bounds [h_min, h_max], [k_min, k_max], [l_min, l_max].

**Suspected Root Causes** (in priority order):

1. **Sign convention mismatch** (HIGH)
   - Scattering vector definition (incident - diffracted) or reciprocal vector orientation may differ from crystal.get_structure_factor() expectations
   - Evidence: Structure factor grid confirmed populated (69,614 nonzero entries, max=2.926e+11), so grid exists and has data

2. **Missing scale/magnitude factor** (MEDIUM)
   - Additional multiplicative constant may be required in Miller index calculation
   - Possible: incident beam normalization, wavelength scaling, or detector-to-crystal coordinate transformation

3. **Grid alignment/indexing convention** (MEDIUM)
   - Structure factor grid may use different indexing convention than physics calculation produces
   - Possible: off-by-one error, reversed axis, or different rounding convention

4. **Rotation matrix bug** (MEDIUM)
   - Reciprocal vectors (rot_a_star, rot_b_star, rot_c_star) may not be properly rotated or rotated in wrong direction
   - Would affect all h,k,l values systematically

5. **Scattering vector calculation error** (LOW)
   - Detector code computing scattering vectors may have sign or normalization issue
