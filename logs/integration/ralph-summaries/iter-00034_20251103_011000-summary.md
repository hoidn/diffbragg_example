## Decisions/Rationales

**Decision 1: Revert to real-space vectors for Miller indices**
- **Rationale**: nanoBragg.c lines 3108-3110 explicitly compute `h = dot_product(a, scattering)` where `a` is the rotated real-space lattice vector in meters. Reciprocal vectors are used only for cross-product calculations to derive direct-space vectors, not for Miller index projection. This is mathematically consistent with the orthogonality relationship: a · b* = 0, a · a* = 1, therefore a · q gives h directly.

**Decision 2: Maintain units consistency (meters & m^-1)**
- **Rationale**: Both scattering vector (m^-1) and real-space vectors (meters) must be in consistent units per nanoBragg.c. The dot product h = a_meters · q_m^-1 yields dimensionless Miller indices. No unit conversion between scattering vector and real-space vectors is needed (contrary to iter-33's approach).

**Decision 3: Use bounded logging for diagnostics**
- **Rationale**: Per input.md and spec requirements, canonical_capture.log must remain <100 lines for HKL diagnostics. Single-line summary with structured output (h=[...], k=[...], l=[...], hit_rate=X%) provides actionable debugging data without log bloat.

**Decision 4: Cross-product derivation of reciprocal vectors**
- **Rationale**: nanoBragg.c lines 2162-2164 show real-space vectors are computed as scaled cross products of reciprocal vectors: a = (b* × c*) × V_cell. Then lines 2185-2187 regenerate reciprocal vectors from real-space: a* = (b × c) × V_star. This bidirectional relationship validates the physics and unit conversions.

## Errors/Failures

### Critical Finding: Miller Index Projection Method Correction

**Initial Hypothesis (iter-33)**: Reciprocal vectors should be used for Miller indices
- Implemented: h = a_star · scattering (converted to Å^-1)
- Result: 0% HKL hit rate (all indices out of grid bounds)

**Root Cause Analysis**:
Through systematic code archaeology of nanoBragg.c (lines 2115-3121):

1. **Vector roles clarified**:
   - Reciprocal vectors (a_star, b_star, c_star) computed from direct-space cross products
   - Real-space vectors (a, b, c) computed from reciprocal-space cross products (lines 2162-2164)
   - Both sets maintain mathematical orthogonality: a · b* = 0, a · a* = 1, etc.

2. **Miller index computation confirmed** (nanoBragg.c:3108-3110):
   ```c
   h = dot_product(a, scattering);      // real-space vector · scattering vector
   k = dot_product(b, scattering);
   l = dot_product(c, scattering);
   ```
   Uses real-space, NOT reciprocal vectors.

3. **Unit analysis**:
   - nanoBragg.c line 215: lambda = 1.0e-10 meters
   - nanoBragg.c line 2999: scattering = (diffracted - incident) / lambda → m^-1
   - Real-space vectors a, b, c in meters (converted at line 3119-3121 for Ångström printing)
   - h = [a_meters] · [scattering_m^-1] = dimensionless ✓

**Suspected Root Cause of iter-33 Failure**:
Iter-33 incorrectly applied reciprocal vector projection based on crystallographic documentation that uses a* notation, missing the bidirectional derivation in nanoBragg.c. The actual implementation uses orthogonality to extract Miller indices via real-space vectors.
