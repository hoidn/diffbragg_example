## Decisions/Rationales

**Rationale 1: Optional fields in GoldenData**
Added `bragg_diffbragg` and `bragg_torch` as optional fields rather than required to maintain backward compatibility with existing test code that relies on the primary `bragg` field. Parity tests can check field presence and conditionally compute correlation metrics.

**Rationale 2: Multi-format loader fallback**
Implemented three-tier fallback (per-panel → torch stack → none) to handle both:
- Legacy per-panel file convention (`bragg_panel_N.npy`)
- New consolidated stack format (`bragg_torch.npy` as `[panel, slow, fast]`)
- Single-panel stacks (2D) for compatibility with prior artifact formats

**Rationale 3: Bool mask coercion**
Coerce uint8 to bool during load to enforce CONFIG-001 binary mask contract and eliminate dtype mismatches between golden generation and fixture consumption. Preserves legacy uint8 fixtures while normalizing to canonical bool representation.

**Rationale 4: Manifest SHA256 validation**
Manifest includes self-checksum for provenance tracking per `docs/spec-db-conformance.md:23-26`. Validates that golden data has not been corrupted between generation and test consumption.

The torch max (2.202339e+13) is approximately 6 orders of magnitude larger than DiffBragg max (36164.90), indicating missing photon-scale normalization or detector gain application in the torch bridge.

**Evidence:** Log entries showing:
- DiffBragg max=36164.90 (physically plausible detector units)

- Parity metrics show median_correlation=-0.0358 (anti-correlation, likely due to scale mismatch)

**Impact:** Parity comparison metrics are degraded but tests still pass because xfail threshold permits expected failures. Future refinement iteration should address scale normalization in torch bridge per `docs/nanobrag_api.md:22-44`.

**Mitigation:** Recorded observation for durable findings; marked as blocker for threshold enforcement in subsequent parity cycles. No code changes required in this iteration (test correctness is preserved).
