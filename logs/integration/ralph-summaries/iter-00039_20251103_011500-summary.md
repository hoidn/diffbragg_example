## Decisions/Rationales

**Decision 1: Remove sqrt(scale_override) multiplier**
- **Rationale**: SCALE-001 finding documented that applying `sqrt(scale_override)` to structure factors was inflating torch output by ~6×10^8 relative to DiffBragg. The canonical capture log from 2025-10-29T181603Z showed torch_max=2.19e13 vs diffbragg_max=3.62e4, indicating the scale was being applied when it shouldn't be.
- **Supporting Evidence**: The multiplier sqrt(3.185e+17) = 5.64e+08, which exactly matches the magnitude difference observed between the two simulators.

**Decision 2: Mark iteration as blocked pending clarification**
- **Rationale**: After removing the multiplier, torch output became too small (6.914e-05 vs diffbragg_max=36164.9), suggesting neither implementation applies scaling automatically. This indicates a fundamental difference in how the two simulators model intensity or a missing configuration parameter.
- **Open Questions**:
  - Does nanobrag_torch internally apply any scale factor to structure factors?
  - Should flux/exposure/beamsize be adjusted to account for DiffBragg's spot_scale_override?
  - Is there a separate scale parameter that should be applied post-simulation?
