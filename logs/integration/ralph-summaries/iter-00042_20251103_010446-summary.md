## Decisions/Rationales

**Decision 1: Pre-flight tensor existence checks before manifest/copy**
- **Rationale**: MANIFEST-001 requires that checksums are computed only over actual generated tensors, not foreign files or partial datasets. Adding checks at lines 660-674 and 723-737 enforces this invariant. Fail-fast behavior prevents silent corruption where manifest might capture wrong paths or missing files.

**Decision 2: Identical validation blocks for manifest and fixture copy**
- **Rationale**: Both operations require the same precondition (4 tensors present). Duplicating the check ensures consistency and clarity rather than extracting to a helper function. Each location has clear, independent failure messages specific to its operation (manifest vs fixture).

**Decision 3: Explicit list of expected tensors in validation**
- **Rationale**: Hard-coding the list `[bragg_diffbragg, bragg_torch, target_panel_0, loss_mask_panel_0]` makes validation intent explicit and testable. This prevents accidental omission if new tensors are added. The list is verified against actual generator output.

**Decision 4: RuntimeError for missing tensors**
- **Rationale**: RuntimeError is appropriate for precondition failures in a generator script. Exit with clear message prevents partially-populated datasets from being archived or manifested. Matches Python conventions for validation failures.
