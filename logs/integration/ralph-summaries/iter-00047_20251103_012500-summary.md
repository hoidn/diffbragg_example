## Summary

Ralph iteration 47 focused on fixing a detector geometry misalignment affecting DB-AT-001 parity tests. The issue stems from torch peaks landing 6 pixels offset from DiffBragg pixels due to incorrect detector convention choice. The loop completed code changes to implement DIALS-convention detector geometry instead of CUSTOM convention, which forces an undesired SAMPLE pivot.

## Key Actions

1. **Analyzed geometry root cause**: Identified that nanobrag_torch's `DetectorConvention.CUSTOM` forces `DetectorPivot.SAMPLE` internally, shifting the beam center from BEAM pivot, causing systematic pixel offsets.

2. **Located spec evidence**: Retrieved nanobrag_torch source code documenting DIALS convention with zero-rotation basis vectors (fdet=[1,0,0], sdet=[0,1,0], odet=[0,0,1]), confirming geometry alignment approach.

3. **Refactored bridge code**: Updated `dbex/nanobrag_bridge.py` to:
   - Add `DIALS` option to `DetectorConvention` enum
   - Replace custom basis vectors with XYZ rotation angles in `DetectorConfig` dataclass
   - Recompute detector geometry using DIALS convention in `create_detector_config()` function

4. **Updated canonical generator**: Modified `scripts/generate_simple_cubic_golden.py` to use `TorchDetectorConvention.DIALS` with rotation angles instead of custom vectors when creating `TorchDetectorConfig` objects.

## Decisions/Rationales

- **DIALS convention chosen**: Preserves BEAM pivot and avoids automatic pivot switching logic triggered by custom vectors. DIALS is the canonical DIALS convention defined in nanobrag_torch (lines 646-650, 1252-1263).

- **Zero rotation angles**: Set detector_rotx/y/z_deg=0.0 to align torch detector frame with DiffBragg's refined detector model, matching canonical tensors pixel-for-pixel.

- **No custom vectors emitted**: Explicitly removed custom_fdet/sdet/odet/beam_vector fields from bridge output to prevent SAMPLE pivot forcing logic in config.py:263-276.

## Errors/Failures

**Root cause**: AttributeError when generator script attempted to access `custom_fdet_vector` on the updated `DetectorConfig` object that no longer has this attribute.

**Fix applied**: Regenerated the generator script to use new DIALS convention fields (`detector_rotx_deg`, `detector_roty_deg`, `detector_rotz_deg`) instead of the removed custom vector attributes. This aligns the generator with the bridge code refactoring.
