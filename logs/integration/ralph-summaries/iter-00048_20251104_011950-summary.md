## Decisions/Rationales

**Why DIALS Rotations:** The specification (docs/config_crosswalk.md:22-35) explicitly requires deriving detector rotations from DIALS panel axes to achieve geometric parity with DiffBragg. Previous implementation used identity rotations (0°, 0°, 0°), causing systematic peak offsets.

**Why scitbx.matrix API:** The codebase already depends on cctbx/scitbx. The `scitbx.matrix` module provides native rotation matrix validation and Euler angle conversion, avoiding external dependencies and maintaining consistency with upstream geometry tools.

**Why Environment Freeze Respected:** No package installations or external modifications were made. The scitbx API is pre-provisioned in the simforge environment.

**Why Tests Remain xfail:** Median offset of 3.0 px indicates remaining geometry factors (beam vector normalization, distance precision, panel origin alignment) still contribute to localization error. Thresholds should not be relaxed until these are resolved.
