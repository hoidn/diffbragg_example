## Decisions & Rationales

### Decision: Implement lightweight calibration loader rather than inline parsing
**Rationale:** Separating calibration metadata extraction into a dedicated function (`load_calibration_metadata`) enables:
- Reuse across multiple test contexts (DB_AT_024, future golden comparison tests)
- Clear error messages for missing/invalid metadata
- Single point of change if DiffBragg config JSON schema evolves
- Testability independent of simulator integration

### Decision: Copy fixture into test suite rather than referencing plans/active
**Rationale:** Per MANIFEST-001 finding, test fixtures must be self-contained and version-controlled within the repository tree to:
- Ensure reproducible test runs across checkouts
- Prevent fixture drift from golden dataset refinements
- Support CI/CD workflows that don't mount external artifact directories
- Maintain fixture identity alongside test code

### Decision: Apply √spot_scale_override post-simulation per SCALE-002
**Rationale:** Structure factors remain unscaled (per SCALE-001); post-simulation scaling applied as global factor because:
- Matches DiffBragg pipeline convention (scale factors applied after physics)
- Decouples intensity calibration from structure-factor sourcing
- Aligns with torch stage A expectations (global_scale as learnable parameter in refinement)
- Preserves future flexibility to source refined Fopt without re-scaling
