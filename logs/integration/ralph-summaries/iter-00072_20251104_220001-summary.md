## Decisions and Rationales

- **Graceful fallback approach**: When `--torch-config` or `--refined-mtz` flags are missing or point to invalid files, CLI warns but continues with default configurations. Rationale: Maintains backward compatibility for existing users while enabling new calibration workflow.

- **Modular config forwarding**: Rather than bundling all calibration logic into `run_nanobrag_backend`, delegated to existing helpers (`create_beam_config`, `create_crystal_config`). Rationale: Follows existing pattern and enables independent testing of each component.

- **Conditional N_cells gating**: `apply_n_cells` parameter only set to True when N_cells metadata is present. Rationale: Prevents accidental application of placeholder values when calibration unavailable.

- **Beam_config as constructor parameter**: Forward `beam_config` object to Simulator constructor (not just individual parameters). Rationale: Enables sample clipping behavior per SCALE-005 architectural requirement.

- **Search-first validation**: Confirmed no duplication by verifying existing helper implementations at nanobrag_bridge.py before extending CLI. Rationale: Avoids code duplication and leverages existing tested functionality.
