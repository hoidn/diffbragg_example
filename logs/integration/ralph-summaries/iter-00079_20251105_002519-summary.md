## Decisions/Rationales

**Design Decision: Tensor override injection vs dxtbx object rebuilding**
- Rationale: dxtbx Crystal object construction requires scalar values (float), forcing `.item()` detachment that breaks autograd graphs
- Solution: Added `crystal_overrides` dict parameter to inject tensor values directly into `crystal_config` after dxtbx object creation
- Trade-off: Crystal overrides implemented; detector/beam parameters still use dxtbx rebuilding (works for gradcheck but less consistent)
- Future consideration: Extend override pattern to detector/beam for architectural consistency (noted as optional next action)

**SPEC Alignment: GRADIENT-001 compliance**
- Requirement: "DB-AT-010 gradcheck harness must avoid `.item()`/`.numpy()` on differentiable tensors; use bridge helpers that accept tensor overrides to preserve autograd graphs" (docs/findings.md:31)
- Implementation: `crystal_overrides` parameter ensures tensor-valued inputs bypass scalar conversion entirely
- Validation: All 4 gradcheck parameter tests passed with tolerances eps=1e-6, atol=1e-5, rtol=0.05

**Runtime Guardrails: RUNTIME-001 enforcement**
- Environment variables `NANOBRAGG_DISABLE_COMPILE=1` and `KMP_DUPLICATE_LIB_OK=TRUE` set in test fixtures
- Prevents torch.compile interference with gradient numerical precision checks
