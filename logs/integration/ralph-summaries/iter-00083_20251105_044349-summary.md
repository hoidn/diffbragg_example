## Decisions/Rationales

### Warm-start from calibration hint

**Decision:** Initialize `log_scale` from `log(global_scale_hint)` rather than `log_scale=0.0` (scale=1.0)

**Rationale:**
- Spec requirement (`docs/spec-db-workflow.md:20-40`) mandates using calibration seed when available
- Prior iteration analysis confirmed `global_scale_hint=62.66` is computed during refinement input preparation
- Starting near optimum reduces risk of LBFGS divergence during early iterations

### Clamping range [-10, 10] for log-scale

**Decision:** Clamp log-scale parameter to [-10, 10] before `torch.exp()`

**Rationale:**
- Previous failure showed `log_scale` diverged to 89.87, causing `torch.exp()` overflow (scale≈1.5e39)
- Range [-10, 10] → scale ∈ [4.5e-5, 22026] covers physically reasonable values
- Clamping preserves gradient flow (smooth) vs. hard parameter bounds (non-smooth)
- Observed optimal value (`log_scale≈7.81`, scale≈2463) falls well within bounds

### Strong Wolfe line search

**Decision:** Enable `line_search_fn="strong_wolfe"` for LBFGS

**Rationale:**
- Default (no line search) allows unconstrained steps that triggered divergence
- Strong Wolfe conditions ensure sufficient decrease and curvature, improving stability
- Standard practice for L-BFGS optimization in high-magnitude loss landscapes

## Errors/Failures and Suspected Root Causes

### Primary Blocker (RESOLVED)

**Error:** `AssertionError: Refinement failed: NaN/Inf gradient detected in 89.86652374267578`

**Root cause:**
- LBFGS initialized `log_scale=0.0` (scale=1.0), far from optimal value (~62.66)
- No line search allowed unconstrained step, overshooting to `log_scale≈89.87`
- `torch.exp(89.87)` ≈ 1.5e39 overflowed, producing NaN/Inf gradients
- Gradient guard at `dbex/nanobrag_refinement.py:233-238` caught overflow and raised AssertionError

**Resolution:**
- Warm-start + clamping + strong_wolfe line search stabilized optimization
- Telemetry now reports `status="early_stop"` (convergence-related) instead of `status="error"`
