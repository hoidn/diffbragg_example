## Errors/Failures and Suspected Root Causes

### HKL Grid Incompatibility (BLOCKER)

**Error signature**:
```
[HKL stats] h=[-17,23] k=[-22,22] l=[0,14] hit_rate=0/6224001 (0.00%)
AssertionError: Loss improvement 0.00% < 5% threshold
```

**Root cause**:
`build_structure_factor_grid` (dbex/nanobrag_bridge.py:559-638) constructs the HKL grid using Miller indices from the original crystal's reciprocal lattice (`refgeom_dataload.F.indices()`). When the crystal is perturbed:
- Cell parameters change (+1-2%)
- Orientation rotates (+1.5° via U matrix)
- nanobrag_torch computes new Miller indices for the perturbed A* matrix
- All computed indices fall outside the original grid bounds → 100% miss rate → zero Bragg intensity

**Impact**:
- Cannot demonstrate ≥5% improvement threshold
- Cannot validate non-zero orientation delta telemetry in smoke test
- Telemetry **implementation** is complete and correct; only **validation** is blocked

**First divergence**: HKL grid lookup at `nanobrag_torch.simulator.Simulator` — all reflections miss grid bounds when crystal geometry differs from grid construction basis

### U Matrix Shape Mismatch (FIXED)

**Error signature**: `TypeError: unsupported operand type(s) for *: 'sqr' and 'tuple'`

**Root cause**: `crystal.get_U()` returns a (9,1) column vector, not a 3×3 matrix

**Fix**: Added `sqr()` conversion: `U = sqr(crystal.get_U())` before applying rotation matrix (L.132-136 in test file)
