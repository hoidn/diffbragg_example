## Decisions/Rationales

**Bridge Helper API Alignment**: Removed `device=` and `dtype=` keyword arguments from all `create_detector_config()` and `create_beam_config()` calls because these helpers do not accept those parameters. This aligns Stage B with Stage A's established pattern and eliminates TypeErrors during detector/beam configuration construction.

**Simulator Instantiation via Models**: Changed from passing raw config dicts to Simulator constructor to first instantiating Detector and Crystal model objects, then passing those models to Simulator. This matches the current nanobrag_torch API expectations and resolves the AttributeError on mask_array tensor conversion.

**Baseline Misset Guards**: Added explicit null checks before tensor addition operations involving `baseline_misset_deg_tensor` because Stage B tests may not provide a baseline_crystal parameter, resulting in None values. Without these guards, Stage B would fail with TypeError on `NoneType + Tensor` operations.

**Stage A Final Parameter Computation**: Computed final refined cell parameters as tensors (cell_a through cell_gamma) from Stage A's optimized log/raw parameters because Stage B's crystal overrides require these values, but they were previously undefined in the scope where Stage B's compute_loss and final render functions execute.
