## Summary

Ralph iteration 121 implemented Phase A4 of PHYSICS-LOSS-001, enforcing a fail-fast sigma_readout guard in the nanobrag CLI backend. The iteration added validation to refuse refinement unless a strictly positive detector readout noise source is available (either via CLI `--sigma-rdout` or calibrated map), plumbed provenance and reference value metadata through RefinementConfig and per-stage telemetry, and updated HDF5 diagnostics output to include new provenance attributes. Tests passed successfully, demonstrating that the CLI now correctly enforces the spec-db-core.md:32-68 requirement.

## Decisions/Rationales

- **Fail-fast over silent defaults**: Spec-db-core.md:32-35 mandates strictly positive variance, so rejecting zero/missing sigma prevents physical nonsense in loss calculations
- **Provenance tracking**: Recording "cli_override" vs "calibrated_map" sources enables downstream diagnostics and auditability of variance model choices
- **Reference value in target units**: Storing ADU-equivalent sigma values (post-conversion if applicable) preserves semantic meaning for telemetry and downstream analysis
- **No defaults to zero**: Changed from implicit `sigma_readout=0` fallback to explicit failure, forcing operators to supply required metadata
- **Priority order (CLI then calibrated)**: CLI provides immediate override path while reserving calibrated maps for future deployment once DataLoad supplies them

## Errors/Failures

- No errors encountered during implementation; tests passed on first run
- Suspected root cause for future work: calibrated sigma maps not yet exposed from DataLoad, so current implementation only supports CLI override path
