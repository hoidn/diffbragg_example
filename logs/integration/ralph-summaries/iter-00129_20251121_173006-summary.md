# Summary

Ralph implemented a Stage A warm cache refactor to optimize the LBFGS closure in nanobrag refinement by hoisting `create_crystal_config()` and `Crystal` instantiation outside the per-panel loop. The refactor reuses cached detector/HKL/mask tensors from `StageAContext` in warm mode while preserving the cold rebuild path for benchmarking. # Decisions/Rationales

- **Hoist Crystal once per closure vs per panel:** The cold benchmark showed detector/crystal/simulator rebuilds dominated per-panel overhead; hoisting to once per loss evaluation removes redundant instantiation in warm mode
- **Stack masks into single tensor:** Consolidates mask reuse inside the loss loop and avoids list index lookups during panel subset extraction
- **Keep cold branch untouched:** Preserves a benchmarking baseline to measure incremental gains; cold mode still rebuilds all structures for reproducible comparison
- **Profile next instead of continuing hoist:** The marginal 1.01× gain indicated the bottleneck shifted to panel-loop simulator work (Simulator.run(), ROI sampling, loss-mask materialization), not object construction
