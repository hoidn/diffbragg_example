# Summary

Ralph iteration 00133 extended warm-cache support to Stage B/C refinement pipeline to achieve performance parity with Stage A. Stage B/C now reuse warmed detector configs/masks from Stage A context and emit performance counters matching Stage A telemetry contracts. Stage C additionally restores best chi-squared snapshots before telemetry emission to prevent loss trace regressions.

# Key Actions

- Refactored Stage B/C warm-cache paths in `dbex/nanobrag_refinement.py` to clone `StageAContext.detector_configs` when warm cache is enabled, allowing panel loops to reuse precomputed masks and beam configs
- Implemented ROI mode fallback logic: Stage C ROI evaluation now consults Stage A panel slices with automatic panel-mode degradation when slices are missing
- Added best chi-squared snapshot tracking and restoration in Stage C before telemetry emission to maintain monotonic non-increasing loss traces
- Instrumented Stage C with perf counters (`cache_mode`, `roi_mode`, ROI totals/sample counts, closure_evals, forward_time_ms`) to match Stage A telemetry contract
- Updated `docs/fix_plan.md` with warm-cache findings (PERF-WARM-006) and implementation details
- Ran smoke tests and confirmed Stage C telemetry integrity

# Decisions/Rationales

- **Warm detector reuse**: Rather than rebuilding detector/simulator configs per panel in Stage C, reuse pre-warmed configs from Stage A context when `enable_stage_a_warm_cache` is active, reducing redundant object construction and memory allocation
- **ROI fallback strategy**: When Stage A does not provide panel slices for Stage C ROI evaluation, degrade to full panel iteration instead of failing; this maintains forward compatibility with Stage A configurations that omit ROI slicing
- **Best-snapshot restoration**: Stage C optimizations can overshoot the best loss; restoring the best chi-squared snapshot before telemetry emission ensures loss_trace_full remains non-increasing and satisfies the Stage C initial = Stage A final test gate
- **Perf counter alignment**: Matching Stage A perf counter names and semantics in Stage C enables cross-stage comparison and validates the warm-cache correctness at the telemetry level

# Errors/Failures

Initial test runs reported `test_stage_c_detector_microslip` failures (loss trace regression detected). Root cause: Stage C was not restoring best chi-squared snapshots and not properly tracking ROI sample counts. Fixes applied iteratively to detector config cloning and loss snapshot restoration resolved the test failures.
