# Callchain Snapshot — Reconstruction vs Stage‑A simulator construction

- **Stage A warm cache builder** (`dbex/refinement/stage_a_utils.py:180-308`)
  - Builds detector configs per panel with the trusted mask injected directly at creation time, converts every `mask_array` tensor to the target `device/dtype`, and instantiates `nanobrag_torch.Detector/Simulator` objects ahead of time so Stage A reuses them through the LBFGS closure.
  - Calibration payload (flux/exposure/beamsize, `N_cells`) is threaded into `create_beam_config`/`create_crystal_config`, mirroring the mapping helper, and oversampling comes from `RefinementConfig.oversample` (default 3).
- **Stage A LBFGS scaling path** (`dbex/refinement/stage_a.py:1189-1315`)
  - Each ROI/panel run multiplies the simulator output by `torch.exp(log_scale_clamped)` where `log_scale_clamped = log_scale_baseline + clamp(delta, ±config.log_scale_max_delta)` in the calibrated case; that baseline is derived from `sqrt(spot_scale_override)` (lines 166-171) so the LBFGS delta is the only movable part.
  - Warm-cache runs keep the simulator’s trusted-mask gating intact (mask tensors already moved to the right device), and ROI validation uses the same `StageAContext` simulators so reconstruction telemetry is consistent.
- **Mapping helper / simulate_forward_once** (`dbex/nanobrag_bridge.py:1296-1510`)
  - Uses the same config factories as Stage A to build detector/beam/crystal configs, always forces `oversample=3`, injects the trusted mask per panel, and after running the simulator multiplies the raw tensor by the factory-provided `sqrt_scale_value` (line 1451) so the returned Bragg tensor already includes the `spot_scale_override` baseline.
- **Reconstruction helper (cold path)** (`dbex/refinement/reconstruction.py:131-320`)
  - Reconstitutes crystal overrides from Stage A telemetry, then enters the cold path when no warm cache is present. The per-panel loop attempts to pass the trusted mask (`inputs.trusted_mask[pid]`) through `create_detector_config` and hardcodes `oversample=3` for parity, but the code never replays the Stage A device/dtype normalization; the `detector_config.mask_array` object is whatever `create_detector_config` returned (CPU float32) and `create_unified_simulator` is invoked with `mask_array=None`, bypassing the normalization branch in `helpers.py:108-133`.
  - `spot_scale_override` is still forwarded only for computing `exp(log_scale_clamped)` (line 279), and `sqrt_spot_scale` is now unused after the earlier double-application fix, so all scaling funnel through the log-scale baseline.
- **Unified simulator factory** (`dbex/refinement/helpers.py:83-190`)
  - Normalizes a provided `mask_array` to the simulator device, builds fresh `Detector/Crystal`, and records the derived `sqrt_scale`. Because the reconstruction helper does not pass the mask explicitly, the factory cannot enforce device/dtype alignment and relies on whatever is embedded in the `DetectorConfig`. In Stage A the warm cache code has already `.to(device)`’d the mask, but the reconstruction path does not repeat that step, so CUDA runs see CPU-hosted masks and silently drop them.

**Key divergence identified:** Stage A warm caches always call `detector_config.mask_array = detector_config.mask_array.to(device, dtype)` before instantiating `Detector`, while the reconstruction cold path never touches the tensor returned by `create_detector_config` and also skips the `create_unified_simulator(..., mask_array=…)` normalization hook. Under CUDA (`RefinementConfig.device="cuda:0"` in DB-AT-028/029), this means the simulator receives a CPU mask in the `DetectorConfig` which is ignored internally, so the reconstruction helper simulates every pixel and reports a raw mean ≈18 % higher than Stage A/mapping despite identical calibration metadata. Passing the mask through the factory (or reproducing the Stage A `.to(device)` logic) is therefore the plausible root cause of the persistent raw-intensity gap.
